# V2 Development

## Goal

Improve the V1 reading experience and add optional AI-powered running recommendations while keeping the local-first tracker simple.

## Improvements

- Larger, more readable typography on desktop and mobile
- Gemini recommendation requested with an explicit button
- Server-side `/api/recommendation` endpoint
- Loading and error states in the recommendation card
- Structured response validation and conservative distance checks
- V1 rule-based recommendation remains visible as analysis and fallback

## Tech stack

- Next.js App Router, React, and TypeScript
- Tailwind CSS with the existing custom dashboard stylesheet
- Browser `localStorage` for activities and runner profile
- Official Google GenAI JavaScript SDK (`@google/genai`) on the server

## Setup

Copy `.env.example` to `.env.local` and set `GEMINI_API_KEY` to enable Gemini. The key is read only in server-side code. Restart Next.js after editing the environment file. Without a key, the tracker and rule-based recommendation still work.

## Current status

V2 implementation is complete. The production build and TypeScript validation have passed. A live Gemini request requires a valid API key and network access.

## Known limitations

- Activities remain in one browser's local storage and are not synchronized.
- AI output is general training guidance, not a personalized coaching plan or medical advice.
- AI suggestions are generated only when requested; there is no recommendation history.
- The app validates the AI response and caps its suggested distance, but cannot assess a runner's health or readiness.

## Next steps

- Manually verify a live Gemini response with a valid key.
- Consider persistent storage only in a later version.
- Consider Strava integration only in a later version.
